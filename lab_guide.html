Lab Overview

Business Problem

5G base stations waste energy during low-traffic periods. AI agents autonomously decide which cells to sleep or wake while maintaining operator-defined QoS.

What Participants Do

Run a live closed-loop AI simulation: set a QoS intent, watch two LLM agents recommend and validate network actions, and inspect the audit trail.

Cloudera Story

Enterprise AI is not just model APIs. It's governed data, secure model serving, auditable decisions, and a platform that works with any model.

Key Outcome

Participants leave with a working project, a results chart, and an agent decisions Parquet file showing every AI decision and its justification.

ℹ️

Lab Configuration

The 7-Step Iteration Loop

StepWhat HappensComponent
1 — PlanLLM #1 analyzes network KPIs via SQL. Outputs Sleep/Wake/No Action per site.Planner LLM
2 — SplitWake actions auto-approved (non-destructive). Only Sleep candidates go to validation.Logic
3 — Sim #1VIAVI TeraVM runs with Sleep actions applied under the next traffic profile.VIAVI RSG
4 — ValidateLLM #2 checks: did QoS stay above threshold? Approves or rejects each action with reason.Validator LLM
5 — AdvanceVirtual time Tv moves forward 15 minutes. Traffic profile updates.Clock
6 — Sim #2Approved actions committed. Simulation runs with next profile.VIAVI RSG
7 — FeedbackSim #2 KPIs become input to next iteration's Planner.State

N1 Band (2100 MHz)

Capacity layer — higher throughput, shorter range. Target for sleep/wake decisions.

N12 Band (700 MHz)

Coverage layer — always awake. PRB utilization here is the key safety signal.

Sleep Condition 1

N1 PRB = 0 AND N12 PRB = 0 → no traffic at all, unconditionally safe to sleep.

Sleep Condition 2

N12 PRB < 35% AND N1 PRB < 12% AND QoS ≥ threshold → low load, safe to sleep.

Problem & Architecture

20 min — Slides + Demo

What to Cover

  • →

    Business context

    5G networks over-provision N1 capacity cells. During off-peak hours, significant energy is wasted on cells serving little or no traffic.

  • →

    The solution

    AI agents that read live network KPIs, decide which cells to sleep, test those decisions in a digital twin, validate against a QoS threshold, and commit only safe actions.

  • →

    Architecture walkthrough

    Walk through the diagram above: Planner → Sim #1 → Validator → Sim #2 → feedback loop. Emphasise the two-agent safety model.

  • →

    N1 vs N12 bands

    N12 (700 MHz) = coverage, always on. N1 (2100 MHz) = capacity, can sleep when N12 can absorb the load.

💡

Key talking point

This is running entirely inside the CDP environment. Data never leaves. The LLM is your model, served by your infrastructure. This is enterprise AI — not a SaaS API call.

What to Narrate While It Runs

ITERATION 1/10 | 00:00 UTC | Profile: Night (ratio=0.1)
  Step 1: LLM generating recommendations...
   Generated SQL: WITH site_metrics AS (...)   ← "The agent wrote this SQL itself"
    → 12 recommendations generated: 12 Sleep   ← "Night traffic is low — sleep everything"

  Step 3: RSG Sim #1 (testing 12 Sleep recs, next profile: Early)...
    → avg_thp=6.23 Mbps, sleeping=12/42       ← "Digital twin confirms impact"

  Step 4: LLM validating 12 Sleep recommendations...
    → 10/12 Sleep approved                     ← "Safety gate: 2 rejected"
      ✓ Sleep S1/N1/C1
      ✓ Sleep S2/N1/C1
      ...

  Step 6: RSG Sim #2 (approved actions + next profile)...
    → avg_thp=7.28 Mbps, sleeping=10/42       ← "Final confirmed state"

Point out: Forward-looking validation

Sim #1 uses the next traffic profile. The AI tests decisions against traffic they'll actually face — not current conditions.

Point out: Rejection = safety working

A rejection is a good thing. It means the Validator caught a decision that would have degraded QoS and blocked it before it reached the network.

Point out: No human in the loop

This entire cycle — analysis, simulation, validation, commit — runs autonomously. The operator only set an intent once.

ℹ️

Embedding Models vs Chat Models

Models like nvidia/llama-3.2-nv-embedqa-1b-v2 are embedding models — they output vectors, not text. They cannot be used as drop-in replacements for the Planner or Validator agents. They are used in RAG pipelines for semantic search and document retrieval.
